# Framework Reference Map

Status: Phase 0 deliverable. Details and code paths are in [repository-analysis.md](repository-analysis.md).

"DS" means DeepSeek Harness. "TF" means TrueForge. Paths are relative to each repository root.

**Include in Harness** takes one of these values:

| Value | Meaning |
|---|---|
| **Core** | Always present |
| **Built-in ext** | Ships in the package, optional |
| **Interface only** | Protocol ships; the implementation is up to the user or a later phase |
| **Defer** | Revisit only if needed |
| **Exclude** | Out of scope |

| Capability | DeepSeek Reference | TrueForge Reference | Design Lesson | Include in Harness | Phase |
|---|---|---|---|---|---|
| Runtime | `core/agent-loop/src/index.ts` `AgentLoop` (factory, transactional create/dispose); `core/agent` `AgentRegistry` | `agent-session/SessionHandle.ts` `createTurn`, `TurnHandle.stream()` (single writer, first terminal write wins) | Lifecycle ownership must be explicit and exception-safe. Both repos treat create and dispose as transactions. A Python runtime can do the same with `async with` and `try/finally`, without a DI container. | Core | 1 |
| Agent | `Agent` in `core/agent/src/runtime-types.ts` is a *live handle* (inbox, status, `cancel`, `whenIdle`) | `AgentDefinition` in `core/runtime/AgentDefinition.ts` is a *declarative spec* (model, instruction, toolSets, iterationLimit) | Keep the definition (TF) separate from the running handle (DS). A declarative `Agent` is easy to test, serialize and reuse across runs. Runtime-owned `Execution` objects hold the live state. | Core | 1 |
| Agent Loop | `ReactLoopAgent` in `core/agent-loop/src/agent.ts` runs turn → step → attempt; it has no step cap | `AgentThread.execute()` is a state machine derived from context (`deriveAgentThreadState`), with an iteration cap | Take TF's idea of deriving "what's next" from pending tool calls, which makes resume trivial. Take DS's idea of keeping policy out of the loop. Add a hard `max_steps`, which DS lacks. | Core | 1 |
| LLM abstraction | `LlmAdapter.stream()` in `llm/llm/src/index.ts`; neutral `StreamChunk`; errors arrive in the stream with neutral codes | `ILLM.create()` in `core/llm/ILLM.ts` uses the OpenAI shape; Vercel AI SDK only as an adapter | DS's neutral vocabulary keeps provider details out of the core. TF shows that an SDK can serve as a single-step adapter only. We will use an `LLMProvider` protocol with `generate()` (and `stream()` later) and neutral `FinishReason` and `Usage`. | Core (interface + mock); adapters are extensions | 1 (stream: 8) |
| Messages | `llm/llm/src/message.ts`: roles system/developer/user/assistant/tool; content blocks; `source` provenance; frozen | OpenAI `ChatCompletionMessageParam` plus extensions (`thinking_blocks`, `tool_info`) | Use content parts over a single string so tool calls, images and reasoning fit without schema changes. Keep a `metadata` field for provenance (DS `source`). Never leak provider fields into the core. | Core | 1 |
| Tool abstraction | `ToolDefinition` in `core/tools/src/index.ts`: JSON-schema params, output schema, render, `isConcurrencySafe`, `timeoutMs`; returns a value | `IToolSet` / `LocalToolMCP.defineTool` in `core/mcp/`: zod schema, `CallToolResponse` union of control-flow outcomes | Tools return data, never exceptions (both). We will use Pydantic for argument models and generated schemas. Add optional metadata (`concurrency_safe`, `timeout`, `read_only`/`destructive`) now so later phases need no interface change. | Core | 1 |
| Tool registry | `ToolRuntime` (`ctx.tools`): scoped register/shadow, `restrict`, `guard`, `schemas()`, `tools/change` | Rebuilt per thread per turn in `convertMCPServers.ts`: name sanitizing, collision suffixes, `toolMapping` | A plain registry object (register, unregister, get, schemas) owned by an agent or runtime; no globals. Validate and sanitize names (TF). Scoped child registries (DS) arrive with subagents. | Core | 1 |
| Tool execution | Pipeline in `agent-loop/src/tool-calls.ts`: plan → classify → pre-execute → guards → execute (around) → post-execute → result, committed in model order | `executeToolCalls.ts`: `Promise.all`, try/catch per call, then `ToolResponseProcessor`s | Phase 1 needs a `ToolExecutor` interface with a sequential implementation. Phase 4 replaces it with DS-style staged pipeline hooks, with **no loop changes**. Always emit a result for every call id (both). | Core (simple) → Built-in (pipeline) | 1, 4 |
| Context | `SystemPrompt` sections with numeric order, contexts, variables; runtime-context projection; "model-visible means logged" invariant | `transformToLLMRequest`, `InstructionBuilder` XML sections, `preLLMEphemeral` transforms, token attribution | A dedicated `ContextManager` builds the `LLMRequest` from state. Use ordered sections (both repos converged on this). Reductions are a view over immutable history, never an edit. Drop DS's full logging invariant because it costs too much. | Core (interface + default) | 3 |
| State | The session event log is the truth; the agent keeps transient phase only | Per-thread `context` array plus capability state KV; the state machine is derived from context | `AgentState` (Pydantic): messages, step, status, usage, metadata, result, plus a namespaced `extensions` KV (TF `capability_state`). Keep it serializable from day one. | Core | 1 |
| Events | Three domains: durable session events, live `agent/*` (with a mode per event), capability `tools/*`; `emit` vs `waterfall` | `core/events/schema.ts` wire events, passthrough events via declaration merging | Separate **observation** (event bus → observers) from **interception** (hooks). Events are immutable Pydantic records with type, timestamp, execution_id, agent_id, payload. Observer failures are contained. | Core (bus) | 5 |
| Observability | `session-telemetry` (+ redaction waterfall), `session-telemetry-otel` (logs), `token-meter` | `AgentTracing` span interface (no-op in OSS), `AgentThreadMetrics`, `computeAssistantMessageUsage` | An `Observer` protocol with a built-in `MetricsObserver` covering runtime, LLM, tool and agent metrics. Platform exporters (OTel, logging) are optional adapters. Cost is computed only if the provider reports it or the user supplies a price table. | Built-in ext | 6 |
| Retry | `llm-retry` plugin on the `agent/request-error` waterfall; neutral retryable codes; backoff + jitter; honors retry-after | None (`maxRetries: 0` in `VercelAILLM.ts:953`); single retries in MCP and sandbox | Retry is policy, not loop code (DS). Classify on neutral `LLMError.code` and `retryable`. Put it in the LLM call path as a wrapper, so the loop body is unchanged. | Core (policy object) | 2 |
| Loop protection | None in core; `guard/repeat-tool-reminder` (advisory at 3/5/8), `guard/timeout-policy` | `iterationLimit` (25 in code, 100 in spec), 600 s turn wall clock, `finish_reason=length` → error | Hard `max_steps` and `max_execution_time` in the core, which DS lacks. Repeated-call detection is a configurable policy (warn or stop), as in DS but able to stop the run. | Core | 2 |
| Persistence | `SessionPersistence` + JSONL provider as a `session/event` listener; single-writer lease; `session/flush` barrier | `ISessionStore` (SQLite/Postgres/in-memory) + contract test suite; persist before mutate; copy-on-write context ids | A `PersistenceStore` protocol with an in-memory implementation and optionally a JSONL file. Save a checkpoint at step boundaries and append events. A shared **contract test suite** for store implementations (TF). No database in the core. | Interface + in-memory | 9 |
| Streaming | `agent/assistant-stream` transient frames vs durable events; WebSocket mux; ACP sends whole messages | SSE custom protocol; deltas streamed, never persisted; resumable via Last-Event-ID | Keep the two channels apart (both do): `runtime.stream()` yields agent events, and token deltas are a separate, transient event kind that is never persisted. Transports (SSE, WebSocket) are application concerns. | Built-in ext | 8 |
| Large result handling | `spill-policy` on `tools/post-execute` + `SpillStore.saveText()` → head…tail + locator; best effort | `LargeToolResponse.ts`: per-call (6k) and per-step total (10k) thresholds, offload largest first, sandbox artifact | A `ResultProcessor` stage in the tool pipeline with inline/truncate/offload strategies behind an `ArtifactStore` protocol (DS seam). Enforce both the per-call and the per-step budget (TF). Offloading must not require a sandbox. | Built-in ext | 7 |
| Compaction | `CompactionEngine` + `compaction-basic`: prune → select region (keep tail, pair tools) → summarize with cache-friendly prefix → shadow range; triggers on pressure and on overflow error | `ContextCompaction` preLLM: summarize the whole context, overwrite it, keep no tail | `Compactor` protocol, called only by the `ContextManager` when the budget is exceeded. Use DS's algorithm (tail, pairing, cheap prune first) and TF's single integration point. History is never deleted; store a compaction checkpoint instead. | Built-in ext | 10 |
| Subagents | `ctx.subagents` provider registry, spawn/fork, own session, scoped ctx, `maxDepth` 1, parent-abort cascade, background jobs | `create_sub_agent` sentinel → orchestrator thread; empty context; shared tools and sandbox; final text only; depth 1 | A `SubagentTool` that runs a child `Agent` through the same `Runtime` with fresh state. The parent sees only the result. Linked cancellation, timeout, depth limit, and child events tagged with the parent execution id. No loop changes. | Built-in ext | 11 |
| Parallel execution | Opt-in `isConcurrencySafe`, rolling pool (`DEFAULT_MAX_PARALLEL_TOOL_CALLS = 10`), exclusive barriers, commits in model order | `Promise.all` without a cap; subagents in chunks of 5 | Concurrency is opt-in per tool, with a bounded `asyncio` semaphore pool and results committed in model order (DS). A sliding pool, not chunks. Failure isolation per call. | Built-in ext | 12 |
| MCP | `mcp-client` plugin per server; tools become ordinary registry entries `mcp__server__tool`; reconnect supervisor; `listChanged` | `RemoteMCP` (source) / `ToolSet` (policy) split; transport probe; timeouts; SSRF guard; deferred loading | An adapter that turns MCP tools into ordinary `Tool`s, so every pipeline policy applies (DS). Keep source and policy separate (TF). The `mcp` package is an optional dependency, never imported by the core. | Built-in ext (optional extra) | 13 |
| Sandbox | `SandboxProvider.confine(argv)` fails closed; bwrap/Seatbelt/ACL | `SandboxProvider` (Daytona), lazy provisioning, Code Mode bridge keeps credentials out | The harness does not run code. Define a `Sandbox` protocol for tools that need one; implementations are external. Credential isolation is a documented requirement, not core code. | Interface only | 14 |
| Human approval | `tools/pre-execute` → `ask` → `ApprovalService` → answerers waterfall; fails closed; `approval/asked|decided` events | Turn ends with `required_actions`; resume with a new turn; approval defaults from MCP annotations (`@write`, `@destructive`) | The policy hook returns `allow`, `deny` or `ask`. `ask` goes to an async `ApprovalHandler`. If none is configured, deny. Also support a "suspend" outcome that ends the run as `awaiting_input` with serializable state (TF), which requires a resumable state (Phase 1 design). | **Deferred** (decided in Phase 0 review: HITL not needed now). Keep the `before_tool` allow|deny hook; add `ask` later without interface change. | 14 (deny-only policy); approval deferred |
| Replay | Log derivation; `ProjectionDefinition{init, apply}`; `buildForkSeed`; `interruptedTurnClosers` | Rebuild from per-turn snapshot; `preComputedCompletion` replay for subagents | Replay rebuilds `AgentState` from persisted events (DS projections) and checks it against checkpoints. Fork means copying state at a step boundary. Build on Phase 5 and 9, with no new core types. | Built-in ext | 15 |
| Plugin system | Cordis: services, `inject`, effects with reverse-order dispose, dispatch modes, per-agent scopes, YAML layering | `AgentCapability` bundle; `ITurnResourceResolver` host seam | Formalize a `Plugin`/`Extension` as a bundle of hooks, tools, observers and prompt sections (TF shape) installed onto named hook points (DS semantics), with explicit `setup` and `teardown`. No DI container, no hot reload, no YAML composition. | Core (after stabilizing) | 16 |

## Additional capabilities observed (not in the required list)

| Capability | Source | Decision |
|---|---|---|
| Deferred tool loading (meta-tools `list_tools`, `get_tool_info`, `call_tool`) | TF `DeferredTool.ts` | **Defer.** Revisit with MCP (Phase 13) as a registry *view*, so the loop stays unchanged. |
| Code Mode / programmatic tool calling | TF sandbox `codeMode/`; DS `ptc` mode | **Exclude from core.** It is an application-level tool built on the sandbox protocol. |
| Steering and injection inbox (`steer` / `inject` / `followup`) | DS `agent-loop/src/inbox.ts` | **Defer.** Leave a `pending_inputs` hook so injected context can land at the next step. |
| Transcript repair (synthetic results for dangling calls) | DS `ToolCallRecovery`; TF `OpenToolCallCloser` | **Core, Phase 2.** Required for valid transcripts after cancel or error. |
| Skills (SKILL.md on demand) | TF `sandbox/skills/` | **Exclude.** An application concern, possible later as a prompt-section plugin. |
| Session query / FTS | DS `session-query-sqlite` | **Exclude.** |
| Cross-replica cancellation, resumable SSE | TF Redis request-reply, `EventSubscription` | **Exclude.** Distributed architecture is out of scope. |
